# AGENTS.md - AI Coding Assistant Guidelines

This document provides strict rules, context, and architectural guidelines for AI assistants working on the **Service.app (Primora)** codebase. Always adhere to these rules when generating, refactoring, or reviewing code.

## STRICT RULES (DO NOT VIOLATE)

1. **NO EMOJIS IN UI**: Never use emoji characters (e.g., ⚠️, ✅, 💬) in the frontend UI. Always use professional SVG icons (e.g., Heroicons style) with Tailwind CSS classes for coloring.
2. **ENGLISH UI ONLY**: All user-facing text, labels, placeholders, and error messages in the frontend must be in **formal English**. Do not revert to Indonesian or other languages unless explicitly requested for a specific localized feature.
3. **NO NATIVE DIALOGS**: Never use `window.alert()`, `window.confirm()`, or `window.prompt()`. Always import and use the custom themed modals:
   ```typescript
   import { showAlert, showConfirm, showPrompt } from '../lib/dialog';
   // Usage: await showAlert({ title: 'Error', message: '...', type: 'danger' });
   ```
4. **TYPE SAFETY**: Always use TypeScript. Import types from `src/types/database` (generated by Supabase). Never use `any` unless absolutely unavoidable. Define interfaces for all component props.
5. **NO DIRECT DATABASE MANIPULATION IN FRONTEND**: Frontend code must only interact with the database via the `supabase` client. Never write raw SQL in frontend components.

---

- **Frontend**: React 18, TypeScript, Vite

## DATABASE & SUPABASE RULES

1. **Row Level Security (RLS)**: Assume RLS is strictly enforced. If a query fails silently or returns empty, check if the user has the correct role (`consumer`, `worker`, `admin`) and if the RLS policy allows the action.
2. **Automated Triggers**: Do not manually calculate or update these fields in frontend code; the database handles them via triggers:
   - `current_active_orders` in `profiles` (Updated on order assignment/completion).
   - `assigned_at` and `expected_completion_at` in `orders` (Calculated on worker assignment based on `estimated_hours`).
   - `average_rating` and `total_reviews` in `profiles` (Updated on new review insertion).
3. **Error Handling**: Always wrap Supabase calls in `try...catch` blocks and display user-friendly errors using `showAlert`.

## STYLING & UI GUIDELINES

- **Theme**: Dark mode by default. Use Tailwind semantic colors: `bg-background`, `text-zinc-400`, `border-border`, `bg-surface`.
- **Primary Actions**: Use `bg-primary hover:bg-primary-hover text-white`.
- **Destructive Actions**: Use `text-red-400 hover:text-red-300` or `bg-red-500/10 text-red-400`.
- **Cards**: Use the `glass-card` utility class for elevated containers.
- **Icons**: Use inline SVGs with `className="w-5 h-5"` (or appropriate size) and `stroke="currentColor"` to inherit text colors.

## KEY WORKFLOWS TO UNDERSTAND

### 1. Shopping Cart Flow
- Users select a `Service` and a `Service Tier` (Package).
- Details (UID, Server, Notes) are captured in `ServiceDetail.tsx`.
- Data is pushed to `CartContext` via `addToCart()`.
- Checkout (`Cart.tsx`) loops through cart items and performs a bulk `supabase.from('orders').insert()`.

### 2. Smart Worker Assignment (Admin)
- When assigning a worker, the dropdown sorts workers by:
  1. `is_available === true` AND `is_on_leave === false`
  2. Lowest workload ratio: `(current_active_orders / max_capacity)`
  3. Highest seniority: `senior` (3) > `mid` (2) > `junior` (1)
- Workers at max capacity are `disabled` in the dropdown unless it's a reassignment.

### 3. Order Timeline & Fairness
- The `OrderTracking` page displays an automated timeline.
- If `new Date() > new Date(order.expected_completion_at)`, the UI must show a pulsing red "OVERDUE" badge.
